# Domain documentation

SuperHarry2 uses a single domain context. Before exploring the domain, read the root `GLOSSARY.md` and relevant decisions in `docs/adr/` when present. Use the vocabulary in the glossary for issue titles, design proposals, and tests. Surface any conflict with an existing ADR explicitly.

Use [the architecture and agreed decisions](../architecture.md) and [the milestone acceptance criteria](../milestones.md) for current product context. Add glossary entries and ADRs as domain terms and decisions are resolved.
